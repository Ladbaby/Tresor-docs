📏 Routing Rules

Rules define how Tresor transforms requests before forwarding them. They are optional — basic forwarding works with downstreams and output_model_ids alone. Rules add plugin pipelines and can optionally override the resolved downstream when no alias is present.

⚙️ Configuration​

rules:
  - id: chat-anthropic
    name: Chat Completions -> Anthropic
    pattern_path: /v1/chat/completions
    pattern_model: gpt-4o             # Optional: only match this model
    active_downstream: anthropic
    pipeline_config:
      - plugin_id: openai2anthropic   # Transform OpenAI -> Anthropic format
    is_enabled: true

  - id: catch-all
    name: Default Route
    pattern_path: "*"                  # Catch-all for unmatched paths
    active_downstream: openai
    pipeline_config: []                # No transformation
    is_enabled: true

Fields​

FieldRequiredDescription
idYesUnique identifier
nameYesDisplay name for the web UI
pattern_pathYesURL path to match (exact path or * wildcard)
pattern_modelOptionalModel name filter — only match requests using this model
active_downstreamYesDefault downstream ID for matched requests (used when no alias exists)
pipeline_configYesOrdered list of transform plugins and their config
is_enabledYesToggle rule on/off without deleting it

🎯 Rule Matching Priority​

When multiple rules could match a request, Tresor selects the best one:

  1. 🥇 Exact path + exact model (highest priority) — e.g., /v1/chat/completions + gpt-4o
  2. 🥈 Exact path, no model filter — e.g., /v1/chat/completions matches any model
  3. 🥉 Wildcard (*) — matches all unmatched paths (lowest priority)

If no rule matches, forwarding still proceeds with an empty pipeline (no transforms).

🔌 Pipeline Configuration​

The pipeline_config defines an ordered list of plugins to execute. Each step specifies a plugin ID and optional configuration:

pipeline_config:
  - plugin_id: custom_header
    config:
      headers:
        X-Custom-Header: my-value
  - plugin_id: openai2anthropic

Plugins execute sequentially — each plugin's output becomes the next plugin's input. Order matters. ⚡

Available Plugins​

Plugin IDDescription
custom_header➕ Inject arbitrary HTTP headers into forwarded requests
openai2anthropic🔄 Convert OpenAI Chat Completion format to Anthropic Messages format (and vice versa for responses)
anthropic2openai🔄 Convert Anthropic Messages format to OpenAI Chat Completion format (and vice versa for responses)
fix_anthropic_images🖼️ Extract images from nested tool_result.content[] arrays and promote them to top-level message content

See the /Tresor-docs/docs/dev/plugin-system documentation in the Developer Guide for details on each plugin's configuration options.

⚡ Auto-Translation​

When a downstream declares api_formats and the incoming request uses a different format, Tresor automatically inserts the appropriate format converter — even without an explicit rule. For example, if a request arrives at /v1/chat/completions (OpenAI format) and resolves to a downstream with api_formats: [anthropic], the openai2anthropic plugin is prepended to the pipeline automatically.

🛠️ Managing Rules​

🖥️ Via Web UI​

The Rules tab shows all rules in a table with enable/disable toggles. The edit modal provides a visual pipeline builder for adding, removing, and configuring transform plugins — select a plugin from a dropdown, configure its options through dynamically generated fields, and reorder steps.

💻 Via CLI​

# List all routing rules
./tresor rule list

# Create a new rule
./tresor rule create "Chat Rule" "/v1/chat/completions" openai

# Switch a rule's active downstream
./tresor rule switch chat-rule anthropic

🌐 Via Admin API​

MethodPathDescription
GET/api/rulesList all rules
POST/api/rulesCreate a new rule (validates downstream exists)
GET/api/rules/{id}Get a single rule
PUT/api/rules/{id}Partial update (supports enabled-only toggle or full update)
DELETE/api/rules/{id}Delete a rule
PUT/api/rules/{id}/switchChange active downstream
